# Техническая схема LinkVideo Monitor 0.8.11

## Поток данных

```text
Desktop Duplication producer ─┐
                              ├─ latest-frame buffer ─ raw BGRA ─ FFmpeg encoder ─ LinkVideo
GDI producer ─────────────────┘                         │
                                                       ├─ AAC: WASAPI system audio
                                                       └─ AAC: gated microphone bridge (DirectShow → PCM)
```

Производитель кадров и основной FFmpeg являются независимыми процессами. Ошибка `AcquireNextFrame` завершает только DXGI-производитель. Основной FFmpeg продолжает получать последний реальный кадр с постоянной частотой и не закрывает RTSP-соединение.

## Выбор захвата

- `auto`: Desktop Duplication на Windows 8+; GDI при отсутствии поддержки;
- `dxgi`: Desktop Duplication с переходом на GDI при ошибке;
- `gdi`: только совместимый GDI-захват.

В пользовательском интерфейсе параметр не показывается. При автоматическом переходе на GDI Desktop Duplication проверяется повторно через две минуты. Переключение не останавливает кодировщик.

При блокировке пользовательского сеанса программа использует свежий кадр `winsta0\Winlogon`, полученный системной службой. Искусственный экран LinkVideo больше не создаётся. Пока Windows не предоставила защищённый кадр, остаётся последний реальный кадр, чтобы не разрывать RTSP-сеанс и не показывать ложную заглушку.

## GDI-производитель

GDI-режим выполняется тем же `LinkVideo.Monitor.exe` с аргументом `--gdi-capture`. Используются `BitBlt`/`StretchBlt` с растровой операцией `SRCCOPY`, top-down DIB BGRA и ручная отрисовка курсора через `GetCursorInfo`/`DrawIconEx`. Флаг `CAPTUREBLT` намеренно не применяется: на части Windows и видеодрайверов он вызывает мигание физического курсора при каждом кадре.

## Кодеки и кодировщики

Поддерживаются две группы:

- H.264: `libx264`, `h264_qsv`, `h264_nvenc`, `h264_amf`;
- H.265: `libx265`, `hevc_qsv`, `hevc_nvenc`, `hevc_amf`.

Перед отображением в интерфейсе каждый вариант проверяется тестовым кодированием через комплектный FFmpeg. Аппаратный вариант дополнительно сопоставляется с обнаруженным производителем видеоадаптера. Недоступные варианты в списке не показываются и не могут быть сохранены.

Программный H.264 используется по умолчанию. Для всех кодировщиков применяется GOP ровно 2 секунды. B-frames отключены. CBR является внутренним режимом по умолчанию и не показывается в пользовательском интерфейсе.

## Аудио

Системный звук захватывается WASAPI loopback и передаётся как PCM 48 кГц stereo через локальный канал. Микрофон открывается отдельным дочерним FFmpeg через DirectShow и передаётся в основной кодировщик как PCM через локальный TCP-канал. Между захватом и основным кодировщиком работает программный gate: постоянный режим, активация голосом или push-to-talk. Горячая клавиша выключения микрофона обнуляет PCM, не перезапуская видеопоток.

При включении обоих источников FFmpeg формирует одну дорожку:

```text
[system][microphone] amix -> alimiter -> AAC
```

Для системного звука сохраняется коррекция синхронизации и `asetpts=N/SR/TB`. Микрофон также ресемплируется с асинхронной компенсацией.

## Локальный RTSP

До сохранения и запуска программа пытается открыть `0.0.0.0:<порт>`. Если привязка невозможна, интерфейс сообщает, что порт занят, и MediaMTX не запускается. Порт уже работающего локального MediaMTX этой же программы распознаётся отдельно.

## Защита управления

В приложение встроен только SHA-256-хеш служебного пароля LinkVideo; открытый пароль не сохраняется в конфигурации, реестре или файлах. После успешного ввода локальный интерфейс получает краткоживущий токен управления. Пароль требуется только для защищённых параметров видео, автозапуска, отключения индикатора и ручных команд управления потоком. Выбор экрана, курсор, защита полей, звук, микрофон и перемещение индикатора доступны без пароля.

## История переподключений

Причины автоматических переподключений сохраняются в `reconnect-history.json`. Хранятся время события, причина и код завершения процесса. Размер истории ограничен 200 событиями. Публикационная ссылка и ключ потока в файл не записываются.

## Совместимость и размер

Вся логика fallback и helper-режимы находятся в основном EXE. В поставку не добавлены отдельные SDK, DLL или копии кодировщиков. Размер дистрибутива в основном определяется комплектным FFmpeg.
