# LinkVideo Monitor 0.6.0 — архитектурное изменение

Проблема 0.5.x заключалась в том, что `ddagrab` находился внутри того же FFmpeg, который публиковал RTSP. Ошибка Desktop Duplication завершала весь процесс и создавала разрыв серверного архива.

В 0.6.0 захват стал отдельным производителем кадров. Основной кодировщик не зависит от жизненного цикла Desktop Duplication. Это позволяет автоматически перейти на GDI, повторять последний кадр и сохранить соединение с сервером.

Аппаратные H.264-кодировщики не добавляются отдельными файлами: используются уже включённые в FFmpeg NVENC, QSV и AMF. Обязательный резерв — libx264.
