# Автоматические обновления LinkVideo Monitor

Начиная с 0.8.12 Beta клиент использует публичный канал обновлений без GitHub Personal Access Token в EXE:

`https://raw.githubusercontent.com/WellJons/LinkVideo.Monitor.Updates/main/update-manifest.json`

Приватный репозиторий остаётся источником кода и исходного Release. После публикации Release workflow переносит официальный Setup в `WellJons/LinkVideo.Monitor.Updates`, проверяет SHA-256 публичного asset и только после этого обновляет публичный `update-manifest.json`.

## Поведение клиента

Фоновая служба `LinkVideoMonitorCapture`, работающая как `LocalSystem`, проверяет манифест примерно через 90 секунд после запуска службы и затем каждые 6 часов. Проверка не требует открытого интерфейса Monitor и работает, пока служба установлена.

Любая более новая версия считается обновлением — в том числе небольшой patch-release, например:

- `0.8.12-beta` -> `0.8.13-beta`;
- `0.8.12` -> `0.8.12.1`;
- `0.8.13-beta.1` -> `0.8.13-beta.2`;
- `0.8.13-beta` -> `0.8.13`.

Понижение версии никогда не выполняется. Build metadata после `+` не влияет на порядок версий.

## Безопасность

Перед запуском установщика клиент требует одновременно:

1. HTTPS-ссылку только на Release репозитория `WellJons/LinkVideo.Monitor.Updates`;
2. совпадение версии в манифесте с тегом Release в URL;
3. имя asset вида `LinkVideo.Monitor_*_Setup.exe`;
4. корректную SHA-256 из манифеста;
5. полное совпадение SHA-256 скачанного установщика;
6. ограничение размера установщика (до 256 MiB).

При публикации workflow дополнительно сверяет Setup с `SHA256SUMS` приватного Release, затем загружает его в публичный Release, повторно скачивает публичный asset и проверяет его SHA-256. Манифест обновляется последним, поэтому клиенты не увидят новую версию до появления и проверки установщика.

GitHub-токены в клиентское приложение не встраиваются.

## Установка без окна и UAC

После первоначальной ручной установки 0.8.12 Beta последующие обновления выполняет уже установленная Windows-служба с правами `LocalSystem`. Поэтому окно установщика и новый запрос UAC не показываются.

Установщик сначала полностью распаковывает новую версию во временную папку рядом с установленной программой. Текущий поток в этот момент продолжает работать. Только после успешной подготовки пакета служба и Monitor останавливаются, каталог текущей версии сохраняется как временный rollback, подготовленная версия быстро подменяет рабочий каталог, после чего служба устанавливается и запускается снова.

Если активация новой версии или запуск новой службы завершается ошибкой, установщик возвращает предыдущий каталог и восстанавливает старую службу. Неудачная версия не запускается в бесконечном цикле: создаётся маркер ошибки, и повторные попытки получают увеличивающуюся задержку.

Настройки пользователя, ссылка подключения, журналы, параметры автозапуска и существующие ярлыки находятся вне заменяемого каталога либо намеренно не переписываются silent-update режимом.

## Ошибки сети

Если манифест или Setup временно недоступны, служба повторяет попытки с backoff примерно 5, 10, 20, 40 и максимум 60 минут. После успешной проверки возвращается обычный шестичасовой интервал.

Если уже скачанный installer не проходит SHA-256, обновление не запускается.

## Небольшие патчи

С точки зрения версии небольшой патч устанавливается полностью автоматически. Пока используется полный Setup, а не binary-delta: даже изменение в одном файле приводит к скачиванию полного установщика. Для текущего размера Monitor это намеренно более простой и надёжный вариант — он позволяет одинаково обновлять EXE, FFmpeg и вспомогательные файлы и проще откатывается при ошибке.

Delta-пакеты можно добавить позже как оптимизацию трафика, но они не нужны для автоматической установки patch-release.

## Следующий уровень защиты

Для защиты не только от повреждения файла, но и от компрометации самого update-репозитория рекомендуется подписывать Setup и исполняемые файлы сертификатом Authenticode и перед установкой проверять доверенную подпись издателя через Windows. SHA-256 и ограничение официальным GitHub-каналом уже обязательны, но цифровая подпись издателя является отдельным дополнительным уровнем доверия.
