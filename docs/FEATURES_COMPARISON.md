# Сравнение возможностей и план развития LinkVideo Monitor

Основание для сравнения: перечень возможностей WinDeskCam PRO на странице https://windeskcam.ru/wdc и текущее состояние LinkVideo Monitor 0.6.1 Beta.

## Уже реализовано

- Передача экрана в LinkVideo по RTSP или RTMP.
- Локальная RTSP-трансляция для LinkVideo Server.
- Автозапуск после входа пользователя в Windows.
- Все подключённые мониторы или выбранный монитор.
- Вертикальная ориентация и произвольное расположение мониторов.
- Автоматический захват Desktop Duplication с резервным GDI-режимом.
- Сохранение работающего кодировщика и RTSP-соединения при временной потере Desktop Duplication: передаётся последний кадр, затем захват восстанавливается.
- Автоматический и ручной выбор Intel Quick Sync, NVIDIA NVENC, AMD AMF или программного H.264.
- Системный звук AAC.
- Дистанционная синхронизация настроек и команда перезапуска потока — клиентская часть API.
- Ограниченные очереди кадров и пониженный приоритет фоновых процессов.

## Реализовано частично

### Работа при UAC и переключении рабочего стола

Сейчас программа должна сохранять само соединение и повторять последний доступный кадр. Защищённый рабочий стол UAC и экран входа в систему не захватываются. Для их передачи нужна отдельная архитектура Windows-службы и агента активного сеанса, а также тестирование на Windows 7–11.

### Несколько мониторов и несколько GPU

Произвольное расположение и вертикальные экраны поддерживаются. Конфигурации, где мониторы подключены к разным видеокартам, требуют отдельной проверки и выбора устройства D3D для каждого выхода. GDI остаётся резервом для общего виртуального рабочего стола.

### Централизованное управление

В клиенте есть периодическая синхронизация настроек и выполнение команды перезапуска. Для полноценного централизованного контроля нужен серверный API, статусы устройств, журнал команд и права доступа.

### Массовое развёртывание

Настройки сохраняются при обновлении, но пока нет штатного тихого режима установки, шаблона конфигурации и развёртывания на все учётные записи компьютера.

## Можно добавить следующим этапом

1. Подсветку кликов мыши с отключаемым кружком и настраиваемой длительностью.
2. Отображение только служебных сочетаний клавиш, например Ctrl+C и Alt+Tab, без записи обычного вводимого текста.
3. Выбор сетевого интерфейса для исходящего подключения к LinkVideo.
4. Тихую установку и импорт заранее подготовленного файла настроек для массового развёртывания.
5. Отдельную Windows-службу-наблюдатель, которая запускает пользовательский агент, восстанавливает его после сбоя и не позволяет обычному пользователю остановить службу.
6. Улучшенную работу с несколькими GPU: отдельный D3D-адаптер для каждого монитора и объединение кадров в общем буфере.
7. Снижение нагрузки по активности рабочего стола: уменьшение частоты обработки при полностью статичном изображении без прекращения постоянного видеопотока.
8. Белый список IP для локальной RTSP-трансляции.
9. ONVIF-обнаружение локальной камеры — только если понадобится совместимость с внешними NVR/VMS, а не только с LinkVideo Server.

## Что не стоит включать без отдельного решения

- Офлайн-активацию лицензии: текущая схема LinkVideo использует облачную ссылку подключения и не имеет отдельной локальной лицензии.
- Полный перехват всех клавиш: это повышает риски утечки паролей и превращает функцию в кейлоггер. Допустимо отображать только заранее разрешённые служебные комбинации.
- Обещание фиксированной нагрузки CPU около 5% без испытаний на наборе слабых и современных компьютеров.
