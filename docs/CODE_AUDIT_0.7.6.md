# Аудит кода LinkVideo Monitor 0.7.6 Beta

Дата проверки: 27 июля 2026 года.
Базовая версия: 0.7.5 Beta.

## Что проверено

- жизненный цикл FFmpeg, перезапуски и остановка потока;
- Desktop Duplication, GDI fallback, курсор и сырые BGRA-кадры;
- WASAPI loopback и передача PCM;
- Win+L, UAC, Winlogon, shared memory и системная служба;
- локальный веб-интерфейс и защита loopback API;
- конфигурация, миграция, автозапуск и восстановление после сна;
- MediaMTX и локальная RTSP-трансляция;
- установщик и обновление существующей установки;
- удалённая синхронизация настроек.

## Исправленные дефекты

1. Старый процесс FFmpeg мог после быстрого перезапуска сбросить PID и состояние нового процесса.
2. Сторонний сайт мог отправить изменяющий GET/POST-запрос на локальный API через браузер.
3. При занятом порту 8098 ссылка подключения могла быть отправлена постороннему локальному процессу.
4. `SetThreadExecutionState` устанавливался и снимался с разных OS threads.
5. Heartbeat защищённого захвата обновлялся через удаление файла, создавая краткий ложный разрыв.
6. Служба недостаточно строго проверяла session request.
7. GDI и WASAPI не обрабатывали допустимую частичную запись `io.Writer`.
8. Блокирующая запись кадра удерживала mutex состояния блокировки Windows.
9. Повреждённый конфиг мог быть перезаписан значениями по умолчанию при автозапуске.
10. Обновление EXE и MediaMTX сначала удаляло рабочий файл, а затем пыталось переименовать новый.
11. Отложенный перезапуск после сна мог снова включить остановленный пользователем поток.
12. Неподдерживаемая дистанционная команда могла быть ошибочно отмечена выполненной.
13. В неиспользуемом коде предпросмотра оставался `CAPTUREBLT`.

## Выполненные проверки

- `go test ./...`;
- `go test -race ./...`;
- 100 прогонов тестов со случайным порядком;
- `go vet ./...`;
- кросс-компиляция тестового и рабочего кода для Windows amd64 и Windows 386;
- сборка Windows GUI x64 и однофайлового установщика;
- проверка применимости патча и контрольных SHA-256.

Покрытие автоматическими тестами после аудита: около 26,5% операторов. Основные платформенные ветви WinAPI требуют реального Windows-теста и не могут быть полноценно выполнены в Linux-среде сборки.

## Что остаётся проверить вручную на Windows

- установка поверх 0.7.5 при уже работающей трансляции;
- курсор во время UAC и установки;
- `Win+L`, настоящий Winlogon и резервный экран LinkVideo;
- сон, пробуждение и остановка потока во время двухсекундной задержки;
- 30–60 минут системного звука без рассинхронизации;
- два монитора, разные DPI и разные GPU;
- временная остановка службы `LinkVideoMonitorCapture`;
- сбой питания/принудительное завершение во время сохранения настроек.

## Известные ограничения, не являющиеся новыми регрессиями

- релизный установщик и встроенный FFmpeg остаются только x64;
- локальный RTSP по LAN не имеет аутентификации и должен включаться только в доверенной сети;
- выбор первого LAN-IP может выбрать VPN/виртуальный адаптер;
- настоящий Secure Desktop зависит от установленной и работающей системной службы;
- полное отсутствие дефектов доказать статическим аудитом невозможно.
