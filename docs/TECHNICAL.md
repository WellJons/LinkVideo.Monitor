# Техническая схема LinkVideo Monitor 0.6.0

## Поток данных

```text
Desktop Duplication producer ─┐
                              ├─ latest-frame buffer (2 кадра) ─ raw BGRA ─ FFmpeg encoder ─ LinkVideo
GDI producer ─────────────────┘                                  │
                                                                 └─ AAC из локального PCM-канала
```

Производитель кадров и основной FFmpeg являются независимыми процессами. Ошибка `AcquireNextFrame` завершает только DXGI-производитель. Основной FFmpeg продолжает получать последний кадр с постоянной частотой и не закрывает RTSP-соединение.

## Выбор захвата

- `auto`: Desktop Duplication на Windows 8+; GDI при отсутствии поддержки;
- `dxgi`: Desktop Duplication с обязательным переходом на GDI при ошибке;
- `gdi`: только совместимый GDI-захват.

В пользовательском интерфейсе параметр не показывается. Значение служит для диагностики и будущего удалённого конфигурирования.

При автоматическом переходе на GDI Desktop Duplication проверяется повторно через две минуты. Переключение не останавливает кодировщик.

## GDI-производитель

GDI-режим выполняется тем же `LinkVideo.Monitor.exe` с аргументом `--gdi-capture`. Используются `BitBlt`/`StretchBlt`, top-down DIB BGRA и ручная отрисовка курсора через `GetCursorInfo`/`DrawIconEx`. При временной ошибке чтения экрана содержимое последнего DIB продолжает передаваться.

## Выбор кодировщика

Порядок зависит от обнаруженных видеокарт:

1. `h264_nvenc` для NVIDIA;
2. `h264_qsv` для Intel;
3. `h264_amf` для AMD;
4. `libx264`.

Каждый аппаратный вариант сначала кодирует один тестовый кадр 128×72. Ошибка инициализации в реальном потоке также приводит к исключению варианта и быстрому перезапуску на следующем кодировщике.

Все варианты используют CBR, B-frames 0 и GOP 2 секунды. Для аппаратных кодировщиков SPS/PPS повторяются на ключевых кадрах фильтром `dump_extra`.

## Аудио

WASAPI loopback передаёт PCM 48 кГц stereo через локальный TCP-сокет. Основной FFmpeg применяет:

```text
asetpts=N/SR/TB
```

Входные wall-clock timestamps не используются. При временной смене аудиоустройства bridge поддерживает вход тишиной и повторно запускает WASAPI.

## Совместимость и размер

Вся логика fallback и helper-режимы находятся в основном EXE. В поставку не добавлены отдельные SDK, DLL или копии кодировщиков. Размер по-прежнему в основном определяется встроенным FFmpeg.
